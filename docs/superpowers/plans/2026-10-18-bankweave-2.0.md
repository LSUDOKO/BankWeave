# BankWeave 2.0 plan

Date: 2026-10-18. Deadline: 18 Oct 2026, 23:59 IST.

The 2.0 spec turns BankWeave from a working investigation pipeline into an analyst product:
a Command Center, replayable golden scenarios, a FalkorDB Lab, a deeper case workspace, an
evaluation page, and a simulated hardware trust layer. This plan maps every item in the spec
to code, states what is real and what is simulated, and orders the work so the live demo
stays working throughout.

## Ground rules

- Anything simulated (enclave, POS/ATM twin, Wokwi, VaultKey) is labelled SIMULATED in the
  UI, API responses and README. The cryptography it uses (HMAC, SHA-256/384, ECDSA P-256,
  Ed25519, DH-PSI) is real.
- No invented numbers: every figure on the evaluation page is read from `eval/results/*.json`.
- Every feature is verified against FalkorDB before it is claimed in the README.
- Read-only inspectors (PROFILE, EXPLAIN, Lab cypher) reject write clauses server-side.

Cloud finding: the instance is at its 100 MB `maxmemory` with `noeviction`, so writes fail
with OOM (seen in Render logs). Fix first.

## Step 0: unblock the live deployment

- Measure memory per graph and index on a local reseed of the same slice.
- Reseed the cloud with a footprint that leaves room for case graphs (fewer banks or
  lighter indexes), keep a size guard: case graphs are pruned oldest-first when used memory
  passes 85%.
- `/api/health` reports used/max memory so the Command Center can show it.

## Visual system

- Palette tokens: Deep Navy `#070B14`, Slate `#0F172A` / `#1E293B` glass panels, Cyan
  `#06B6D4` links, Amber `#F59E0B` evidence and needs_verification, Crimson `#EF4444`
  suspicious and superseded, Emerald `#10B981` cleared and active.
- Bank colours stay Okabe-Ito (colourblind-safe) and are checked against the new
  background.

## Phase 1: reliability and replay

- **Command Center** (`/`): active alerts, open cases, independently supported claims,
  evidence awaiting review, FalkorDB health (region, memory, graph count), worker status.
- **Golden scenarios** (`/scenarios`): A innocent alert cleared by `wcc`; B the 4-bank ring
  (43.8% single-bank view vs 100% consortium); C shared A-77 / D00063 for the Skeptic and the
  cascade. Each is a JSON snapshot captured from real API responses and bundled in the
  frontend, so it renders in 0 ms when Render is cold. Every page that can fall back shows
  the mode badge.
- **Mode badge**: LIVE (LLM + FalkorDB), LIVE (deterministic agents), or SEEDED REPLAY.
- **Replay Investigation**: steps through the case `Event` timeline (`HAD_EVENT`, `NEXT`)
  and reveals claims, evidence and actions in the order the agents made them.

## Phase 2: case workspace

- **Evidence Independence Explorer**: paths grouped by `origin`, with a badge such as
  "12 paths → 4 origins" and the echo-proof vs naive confidence.
- **Revoke / supersede evidence**: a button on each evidence card calls the existing
  invalidation, animates the cascade, recomputes confidence, and locks Approve until an
  override note is written.
- **Simulate Freeze**: `GRAPH.COPY` the case graph into a sandbox, remove the account, rerun
  `algo.maxFlow` and `algo.wcc`, report the liquidity and component change, delete the sandbox.
- **SAR provenance inspector**: clicking a sentence highlights its cited claims and
  evidence; export as FinCEN-style XML and as an audit dossier (HTML, printable to PDF) with
  each query's cypher, a SHA-256 hash of every record, a Merkle root and an Ed25519
  signature. Labelled "FinCEN-style": it is not a filed BSA e-file.
- **2D DAG workspace**: React Flow view of Claim / Evidence / Sentence / Action with
  `SUPPORTED_BY`, `CHALLENGED_BY`, `DERIVED_FROM`, `JUSTIFIED_BY`, `SUPERSEDES`.

## Phase 3: FalkorDB Lab (`/lab`)

- Multigraph explorer: every graph with node and edge counts, labels, indexes and
  `GRAPH.MEMORY USAGE`.
- Algorithm runner: the 10 algorithms, phonetic and stemmed full-text, vector KNN; each
  run returns the cypher, rows and timing.
- PROFILE / EXPLAIN inspector (read-only) with the operator tree.
- MCP Tool Explorer: the 33 tools, read-only vs mutating, input schema, run read-only tools
  live and show the cypher they executed.
- Advanced: JS UDF library `aml_temporal` (`timeRespectingReach`), FLEX functions when
  loaded, single-pass tri-modal query (vector + full-text + `algo.SPpaths`), per-bank ACL
  demo with `ACL LOG` (local/Docker; the cloud user cannot run ACL), Engine X-Ray (PROFILE +
  graph memory for any tool's cypher).

## 3D stratified consortium view (`/consortium-3d`)

- `react-force-graph-3d`, lazy-loaded. Bottom plane: bank clusters with ExternalAccount
  stubs; middle plane: consortium accounts with flow particles and PageRank hub size; top
  plane: cases and claims.
- Camera fly-through to the ring, echo-collapse (paths merging into origins), invalidation
  shockwave (Emerald → Amber → Crimson) that locks Approve, kill/resume with a heartbeat
  countdown. Side-by-side bank vs consortium toggle.

## Phase 4: evaluation page (`/evaluation`)

- E2 hero (43.8% / 0% / 100%), E6 scorecard (27.8% echo, 100% cascade on 50 scripted
  graphs, 0 stale approvals), E1 threshold slider over the saved per-account scores (rules
  ≥3: P 33.3% R 7.8% F1 0.126; calibrated P 17.8% R 24.0% F1 0.205), E7 badged as a local
  benchmark. E1 is extended to save the score distribution it already computes.

## Phase 5: integrations (optional, keyless fallback)

- `services/sanctions.py`: OpenSanctions API when `OPENSANCTIONS_API_KEY` is set, otherwise
  a bundled synthetic watchlist slice; every hit carries provenance (source, dataset, fetched
  at).
- Agent telemetry: OpenTelemetry-shaped spans (trace id, span id, parent, attributes) per
  agent step and tool call, stored on the case; Trace Waterfall in the case page.
- DH-PSI handshake between two bank graphs (commutative blinding in RFC 3526 group 14): both
  banks learn only the intersection size and the shared hashed ids. Shown as a badge with the
  transcript.
- Crypto off-ramp bridge: an EVM address lookup adapter with a bundled synthetic fallback,
  linking wallets to accounts as evidence with origin `chain:<address>`.

## Hardware trust layer (all SIMULATED, $0)

- `services/hardware_enclave.py`: simulated HSM/TEE that holds the consortium salt, blinds
  ids with HMAC, reports PCR0/PCR1 measurements and writes `(:EnclaveAttestation)`.
  `POST /api/hardware/enclave-tamper` changes the measured code, attestation fails, the
  enclave goes QUARANTINED and blinding stops; reset restores it. Attestation inspector in an
  AWS Nitro-like document schema (`module_id`, `digest: SHA384`, `pcrs`).
- Approval signing over the case Merkle root: real WebAuthn when the browser has an
  authenticator (or Chrome's virtual authenticator), otherwise "VaultKey (virtual)" using
  WebCrypto ECDSA P-256. Stored as `(:HardwareAttestation)-[:ATTESTS]->(Action)`; if evidence
  later changes, the recomputed root no longer matches and the UI shows MERKLE SEAL BROKEN.
- Virtual ATM/POS twin (`/hardware-lab`): terminals `POS-MUM-D00063` and `ATM-DEL-A00091`,
  three NFC cards, ISO-8583-style logs with real EMV TLV hex (9F02, 9F26, 9F27=80, 9F36,
  9F1E, 5A) decodable at emvlab.org. Presets: mule card-swiping ring on the shared POS, and a
  cloned card used in Mumbai then Delhi faster than travel allows. Taps write transactions
  into the graphs and raise alerts through the normal pipeline.
- `hardware/wokwi/`: ESP32 + SSD1306 + buttons/LEDs circuit (`diagram.json`, `sketch.ino`)
  that posts the same JSON to `POST /api/hardware/pos-tap`.

## Order of work

1. Step 0 (cloud memory) and the palette.
2. Phase 1, then Phase 3 (the spec's stated first actions).
3. Phase 2 and the DAG workspace.
4. Evaluation page, then the 3D view.
5. Hardware layer, integrations, advanced FalkorDB items.
6. README and docs, redeploy Render and Vercel, cloud Browser proof for new features.

Each step lands as small commits with tests where there is logic (Merkle, PSI, EMV TLV,
read-only guard, enclave state machine).
