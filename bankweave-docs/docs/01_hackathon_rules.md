## The brief (verbatim intent)

Build a working agent, or a group of agents, with FalkorDB as its context layer. **The graph has
to shape what the agent does, not sit on the side.** Build an agent that acts on connected data,
remembers what it learns, and can show how it got to each answer.

"Work the graph has to do":
- Follow connections across data
- Remember across sessions
- Share state between agents
- Connect people, projects, and decisions
- Show the path behind an answer

## Hard rules

1. **FalkorDB must be the main graph database** and support a core part of the product.
2. **The graph has to do real work. If the app still works without FalkorDB, it doesn't count.**
3. **Only public, synthetic, or your own data.**
4. Run it any way: Docker, self-hosted, or FalkorDB Cloud; any language/framework.
5. **AI coding tools are allowed — disclose them** and be able to explain your code.
6. The submission and its main FalkorDB implementation must be **new work done during the event**.
   General libraries, templates and infrastructure may be reused.

## BankWeave track strategy

- **Primary: Track 01.** Algorithms as MCP tools, multi-hop investigation, human-approved actions,
  clickable explanations.
- **Secondary: Track 02.** Graph blackboard coordination, per-bank and per-case memory isolation,
  kill-and-resume, cascading invalidation, procedural memory, concurrent agents.
- **Track 03: only if genuinely complete.** A "compliance-team brain" (analysts, past decisions,
  policies, typology docs, decision provenance). Don't enter it half-built.
- **Blog post:** yes. See `13_demo_video_blog.md`.
